# L2: grammatical words, split from L1

Everything `PLAN.md` and `REDESIGN.md` say about generation 2's Layer 2,
gathered in one place, the same way [`L1.md`](L1.md) gathers L1. **L2 is
designed but not implemented** — no `gen2/l2.py`, no rollout run yet.

## What old Layer 2 gets wrong

`PLAN.md`'s handoff (old Layer 2 review, `REDESIGN.md` §6, entry point *Inf*
1:3 `smarrita`): past participles are encoded three incompatible ways
(`pos=verb`+`mood=participle` 724 / standalone `pos=participle` 25 /
`pos=adjective` 573+, the last splitting its own lemma between the adjective
form and the verb infinitive for 104 wordforms; `smarrito` itself splits 4/4).
The `pos` column holds 39 values, not a closed set — subtype leakage
(`relative pronoun`/`pronoun`, `proper noun`/`noun`) plus spacing duplicates
and singletons. Checked against `case/`: `case/` is complete and closed
(13,157 rows, exact match), so the sparseness is not a `case/` coverage gap —
it is a pass-through of Layer 2's `pos` column read verbatim
(`case/case.py:11`), meaning a mistagged `pos` (e.g. a `che` mistagged
`conjunction`, finding B's 225 positions in `reads/inf-1-1-9.md`) never
reaches `case/`'s build step at all. Recorded correction: the working
assumption that "later layers don't lean heavily on `pos`" does not hold for
`case/` specifically.

Also relevant to L2's scope: old Layer 3's fused-enclitic-pronoun mechanism
(`clitic_mentions()`, the `"+lemma"` sentinel span, e.g. *Inf* 1:59
`venendomi` → `np/inferno/01.tsv:59` `+mi`) compensates for old Layer 1 having
no position for a bound pronoun. L2's split table covers exactly this shape
(`verb+pronoun`, 488 tokens / 372 wordforms), so under the rebuilt stack the
pronoun becomes an ordinary L2 entry and the whole synthetic-mention
apparatus has nothing left to compensate for (`REDESIGN.md` §2.2).

## The design (`REDESIGN.md` §2.1)

**L2 splits contractions and clitic compounds into their grammatical words,
and carries a back-reference to the L1 token it came from.** Under premise 3
this is generation 2's own step, not a lookup into old Layer 2's lemma
field — but it is also **independent of grammatical analysis** (operator,
2026-09-09), kept out of the POS-tagging/dependency pass entirely, so a
mistake in one is never entangled with a mistake in the other.

> **Superseded on the split/POS boundary (operator, 2026-09-09), see *Split
> and POS become one pass* below.** Independence was the reason `pel` could
> not be caught: a shape question has no second column to contradict it, and
> the guard has to be answered *at the same position, in the same answer*. The
> split and the coarse POS are now one pass. Everything else in this section —
> the `(l1_index, …)` shape, the split table, the splits-never-merges rule —
> stands; the entries are `(l1_index, text, pos)` triples now.

L2 is an **ordered list of `(l1_index, text)` pairs** — the L2 token number is
its position in that list and is never stored separately, only `l1_index` is
data. A composite L1 token produces **several** L2 entries sharing one
`l1_index` (1:many); every other L1 token, including punctuation, carries
straight through as exactly one L2 entry (1:1). Worked example, *Inf* 1:1
`Nel mezzo del cammin di nostra vita`:

```
L1   0:Nel  1:mezzo  2:del  3:cammin  4:di  5:nostra  6:vita
L2   (0,in) (0,il) (1,mezzo) (2,di) (2,il) (3,cammin) (4,di) (5,nostra) (6,vita)
```

`Nel` (L1 index 0) and `del` (L1 index 2) each yield two L2 entries; every
other L1 token yields one. Nothing downstream that needs the original token
(old Layer 4's `head_line`/`head_token`, say) loses the ability to name it.

### The split table

Old Layer 2's 2,681 composite-POS tokens reduce to **442 distinct wordforms**
(case-folded) — `del` 569, `al` 549, `nel` 310, `dal` 172, `col` 109, … — and
**423 of 442 (95.7%) have exactly one recorded split**, with no dependence on
the sentence around them. Only 19 show more than one, mostly old Layer 2's
own spelling noise on the same lemma (`dimmi` as `dire+me` / `dire+mi`)
rather than real ambiguity; `dal` showing both `da+il` and `di+il` is very
likely an outright error (`dal` is not a form of `di`), while `nel` genuinely
splits two ways (`in+il` the ordinary contraction vs. `ne+lo` the pronoun
compound) — real but rare. **L2 is therefore a static lookup table plus a
handful of flagged exceptions, structurally the same device `tokenizer.py`'s
`quote_cases.txt` already is for apostrophe normalization** — not a
grammatical judgement, and not an LLM call. Old Layer 2's decomposition data
is precedent for building and checking that table, not an input the running
split reads.

### L2 only splits; it never merges (operator, 2026-09-09)

`l1_index` is always a single integer, never a tuple — so a many:1 direction
(several L1 tokens = one grammatical word) is not a shape L2 takes, even
though the corpus already has that phenomenon: old Layer 4's `fixed`
relation, **170 groups**, almost all complex prepositions (`in su`, `dietro
a`, `presso a`, `per entro`, …), 169 of size 2 and one of size 3 (*Par*
32:133 `Di contr'a`), every one contiguous. Merging was tried at this level
and measured to conflict with splitting: **37 of 170 fixed groups (21.8%)
have a member that is itself a composite-POS token**. *Inf* 7:130 is the
clean case —

```
130:7  al = a+il  (preposition+article), fixed head
130:8  da          (preposition),        fixed child
```

— the multiword expression is `a da` ("at last"), not `al da`: only the `a`
half of `al` participates, `il` does not. A tuple `l1_index` naming both L1
tokens would claim `il` belongs to the fixed group, which is false.
Decomposition must go all the way down first — every token split to its
finest grammatical-word grain — before anything is put back together. **The
merge stays exactly where the corpus already puts it: a `fixed`-style edge
one layer up (L4, over L2 entries), not a second, conflicting join built
into L2 itself.** L4 gets this cheaply for the 133 non-conflicting groups and
correctly for the 37 conflicting ones, because at the L2 level `a` and `il`
are already two separate, addressable entries and the edge can point at
exactly `a`.

### Normalization: apocope and elision, to the surface form (operator, 2026-09-09)

`i'` is `io` with its final vowel restored, and that stops at `io`; it does
not continue on to a lemma, because for this wordform they happen to
coincide. They do not always: `son` restores to `sono`, and `essere` stays
where it already is, as the lemma a later, independent pass assigns. Measured
over old Layer 2's `apocope`/`elision`-noted, non-composite rows:

```
apostrophe-marked   (l', 'l, ch', d', s', m', t', 'n, com', i', …)   300 wordforms   7,047 tokens
no apostrophe       (son, eran, avea, vuol, gran, cor, tal, …)     1,386 wordforms   6,909 tokens
```

The apostrophe-marked set is exactly as clean as the split table — the
boundary is visible, restoration is one vowel, and the lemma is usually the
same closed-class word anyway. The no-apostrophe set is not: **477 of 1,510
distinct (word, lemma, pos) rows have a lemma that is not a simple extension
of the surface spelling** — `son`/`eran`/`avea`/`vuol`/`furon`/`convien`
restore to inflected forms (`sono`, `erano`, `aveva`, `vuole`, `furono`,
`conviene`) that the lemma (`essere`, `volere`, `convenire`, …) never
records, because the lemma is the infinitive and the restored form is not.
Old Layer 2 is therefore precedent for the split table but **not sufficient
data** for the normalization table — the target text has to be constructed,
not read off an existing column.

**A further 159 wordforms cross more than one POS** (`l'` → `lo`/`la`,
`fuor` → adverb `fuori` / verb, `qual` → four different POS across its
occurrences), and for these the restored spelling depends on which reading
applies — `l'` restores to `lo` or `la` only once gender is known.

### Why the pipeline is three steps, in this order

> **Steps 1 and 2 are one step now (operator, 2026-09-09); the *ordering*
> argument below survives unchanged.** What this section actually establishes
> is that **normalization comes last**, after the POS is known — `l'` -> `lo`
> needs step 2's answer — and that is still true. What changed is only that
> steps 1 and 2 are asked together rather than one after the other, which
> gives normalization both of its inputs at once instead of in sequence. See
> *Split and POS become one pass*.

**Desk check, two lines (operator, 2026-09-09): the 159 cross-POS wordforms
are not an exception, they are the reason the pipeline has three steps in
this order.**

```
1. split          — L1 -> L2, closed-vocabulary, as designed above
2. POS             — per L2 entry, independent grammatical classification
3. normalize       — restore apocope/elision, keyed on (L2 text, POS from step 2)
```

*Inf* 1:1 `Nel mezzo del cammin di nostra vita`:

```
L1        0:Nel 1:mezzo 2:del 3:cammin 4:di 5:nostra 6:vita
1.split   (0,in)(0,il) (1,mezzo) (2,di)(2,il) (3,cammin) (4,di) (5,nostra) (6,vita)
2.POS     in=prep il=art mezzo=noun di=prep il=art cammin=noun di=prep nostra=adj vita=noun
3.normal. in→in il→il mezzo→mezzo di→di il→il cammin→cammino di→di nostra→nostra vita→vita
```

*Inf* 1:25 `così l'animo mio, ch'ancor fuggiva,` — no composite tokens, so
step 1 is the identity, but step 3 needs step 2's answer for `l'`:

```
L1        0:così 1:l' 2:animo 3:mio 4:, 5:ch' 6:ancor 7:fuggiva 8:,
2.POS     l'=article, gender/number undetermined until agreement with 2:animo
          (masc.sg) is resolved in the same pass
3.normal. l'→lo (only decidable once step 2 has fixed masc.sg); ch'→che;
          ancor→ancora; everything else passes through unchanged
```

**So the 159 wordforms are not a scoped exception: normalizing strictly
after POS, for every wordform, is simply step 3 following step 2 in a
three-step pipeline.** No `(wordform, pos)`-keyed carve-out is needed; the
ordering already gives every wordform its POS before normalization asks for
it. The other 1,527 wordforms just have a trivial step 2 → step 3 dependency
(the POS doesn't change the answer), not a different mechanism.

### Step 2 should be staged (operator, 2026-09-09)

Old Layer 2 asked for the whole row — POS, gender, number, person, tense,
mood — in a single judgment, and the participle finding above is what that
produces: deciding `verb`, `present participle`, `m.`, `sg.` together gives
the model enough surface area to substitute `adjective` for `verb`+participle
right at the one boundary where the two readings overlap. The fix is not
asking for less, it is asking **in stages** — a coarse category first, from a
closed set, then a further classification *within* that category (verb:
tense/mood/person/number; noun: gender/number; …), with the granularity of
the second stage decided separately, later. A coarse-only first pass is also
what would have kept the 39-value drift closed in the first place.

**The participle/adjective boundary needs pinning down explicitly, not just
staging.** Staging alone does not settle it: a participle stays `verb` at the
coarse stage only if the coarse-stage prompt or a one-shot example states the
rule, because "is this a verb or an adjective" is exactly the judgment the
model already answers both ways for the identical wordform (`smarrito` split
4/4). The design needs a stated convention — participles are `verb` at the
coarse stage regardless of predicative or attributive use, with the surface
reading recorded as a fine-grained tag under `verb`, never by relabeling the
coarse category — and a one-shot example enforcing it, not left implicit the
way old Layer 2 left it.

### The concrete task (operator, 2026-09-09)

> **Two passes, not three (operator, 2026-09-09).** The split table and the
> per-entry POS are built by one pass now; the diff against old Layer 2 is
> unchanged and gains a second half, its `pos` column beside its `lemma` one.
> See *Split and POS become one pass*.

Build the 442-wordform split table, the per-L2-entry POS classification, and
the ~1,686-wordform normalization table as **three separate passes in that
order**, with no view of old Layer 2, then **diff each against old Layer 2's
composite-POS/lemma field** as the precedent check — the same methodology
already standing in `PLAN.md` §2 and every `*/CORRECTIONS.md`: classify by
cause before touching anything, verify each row against an existing
precedent row. Three outcomes fall out, not two: the new table agrees (423
wordforms for the split table, expected); the new table disagrees and old
Layer 2 is the one that's wrong (`dal`'s `di+il` is the found candidate); or
the disagreement is genuine synchronic ambiguity the table must keep both
branches for (`nel`, and the 159 cross-POS wordforms, resolved by pipeline
order rather than a carve-out). Because normalization only ever consumes step
2's POS and never the other way around, a disagreement is never confounded
with a POS-tagging mistake.

### Execution mechanism

**Already exists (operator, 2026-09-09): `harness/`'s fixed-context step**
([`../harness/stages/09.md`](../harness/stages/09.md) §2). Each of the three
steps above, for each wordform, is one step `P -> O -> State Σ ()`: $P$ the
single instruction for that step ("split this token" / "classify this
entry's POS" / "restore this entry's spelling"), $O$ old Layer 2's row for it
(bootstrap precedent, premise 3) plus, for step 3, step 2's own output, $\Sigma$
the candidate entry, output the accepted text — and, per §9's design, **no
transcript carries between steps or between wordforms**, because each is
independent and a growing history buys nothing a stateless step doesn't
already have. Up to 3 × (442 + ~1,686) steps, each with a verdict (agrees /
precedent-is-wrong / genuine ambiguity) and no per-iteration context growth.

**One step, one job.** The three jobs are never compressed into one request —
against harness's own finding that batching is exactly where failures
concentrate (`harness/stages/09.md` §2, "Full rows, not a patch": 68% of the
paper it reviews attributes its failures to botched multi-key merges).

**Correction (operator, 2026-09-09): one *wordform* per request was wrong,
and is superseded by old Layer 2's own granularity — a chunk of lines,
`--chunk`, default 3.** This paragraph originally extended "no batching" from
the three jobs to the wordforms as well. That does not survive contact with a
request-rate limit: *Inf* 1:1-9 alone is 56 distinct wordforms against 3
chunks, and the corpus-wide table is 442. **The argument against batching does
not reach this case**, because a chunk is still *one job* asked over more
material — split these tokens — not split-plus-POS-plus-normalize merged into
one answer. The failure mode `stages/09.md` measures is a multi-key *merge*;
there is no merge here, only a list whose length the runtime knows in advance.

Two things follow, and both are improvements rather than costs:

- **The answer carries differences only** (operator, 2026-09-09, on seeing a
  real chunk answer: 27 rows to convey one fact). The request lists the
  chunk's L1 tokens; the answer names **only the tokens that split**, and a
  token with no row is recorded as a single word. *Inf* 7-9's real answer is
  one row, `del:di+il`. A key that names two places in the passage is refused
  and the model is told to prefix it with the preceding tokens
  (`trattar del:di+il`) — the target is the key's last word — which is also
  how a wordform genuinely splitting two ways in one passage gets said. **What
  this gives up, stated:** the one-row-per-token contract proved the model had
  produced a judgment for every token; an empty block is now
  indistinguishable from a model that did not look. `--check` against old
  Layer 2 is the after-the-fact detector, where a missed split shows as
  `differs`.
- **The alignment check is exact where it applies.** Each key is resolved
  against the tokens the request listed: it is exactly one token of this
  passage or the answer is refused. Old Layer 2
  needed `morph.align_chunk` for a different reason than a missing token
  layer: `tokenizer.tokenize()` predates both layers and
  `morph.validate_line` already checks rows against it. The reason is that
  `morph/morph.py`'s prompt shows only the raw lines and asks the model to
  *do the tokenizing too* ("emit exactly one row per word … separate words
  linked by an apostrophe into separate rows"), so its table has to be mapped
  back onto the lines afterwards — `morph.split_table` substring-matches the
  `Word` column with FIFO salvage at line boundaries, "tolerating LLM word
  transforms/hallucinations", and validation reports the damage after the
  fact. Listing the tokens in the request turns that tolerant post-hoc match
  into a gate the answer either passes or is refused by.
- **Repetition becomes a consistency check, and splits become per-occurrence.**
  A wordform occurring in two chunks is asked twice, and **both readings are
  kept**: `gen2/l2.py` records a split at `(line, l1_index)`, not against a
  wordform-keyed table, so `nel` = `in+il` at 1:1 and `ne+lo` at 3:2 can both
  be true. A later occurrence answered differently from the first is recorded
  as a **conflict** on that chunk and then applied as answered — the model had
  that passage in front of it. This is exactly the handful of flagged
  exceptions this file already predicts (old Layer 2's own `dimmi` noise is
  the same shape), and the per-wordform granularity could not perform the
  check at all. The wordform-keyed table this file describes is then what a
  corpus-wide run *derives* from these occurrences, with the disagreements
  visible instead of averaged away.

**A chunk that never passes the gate degrades to line by line**, which is
`morph.py`'s own fallback ("chunk failed, retrying line by line"), so one bad
group costs its own lines and not the run.

**The split step's output is keyed by the word, not by `l1_index`.** (This
survives the granularity correction above unchanged — a chunk's answer is a
list of `word:split` rows, still never an index.)
Writing the answer as `1:in`, `1:il` — echoing the numeric index back for
each half of the split — puts load on the model the task doesn't need:
getting the split right and copying a number correctly are two different
failure modes bundled into one answer, and only the first is what step 1 is
actually asking. The step should instead ask for `nel:in+il` — the surface
word as the key, its split as the value — with `l1_index` attached by code
afterward from the wordform's own position, the same way alignment already
anchors Layer 3 spans to tokens without asking the model to state indices.
**The ambiguity retry this paragraph originally specified is gone with the
granularity change**: it existed because a wordform asked in isolation
sometimes cannot be decided (the `nel` two-way case). A chunk carries its
lines, so the model has the context that question needed and answers the
reading this passage takes; a disagreement across chunks surfaces as a
recorded conflict instead. This is an implementation detail of step 1
specifically — it does not change
the split table's scope or the three-step ordering.

### Cost, stated once (`REDESIGN.md` §5)

```
composite-POS tokens          2,681
terminals after splitting     5,374   (+2,693)
corpus                      101,601 → 104,294   (+2.65%)
```

Almost all are two-way splits; three-way ones are `verb+pronoun+pronoun` (6)
and `preposition+article+noun` (4). The largest classes:

```
preposition+article 1,984   verb+pronoun 488   pronoun+pronoun 61
pronoun+preposition 58      adverb+pronoun 42  preposition+noun 12
```

**What the current merge costs, measured.** Of the 1,984 `preposition+article`
tokens, Layer 4 can only give the token one `deprel`, which goes to the
preposition half; the article half gets no edge. The noun it determines
therefore has **no determiner child in 1,666 cases**. The 318 exceptions
carry a separate `det:poss` (294) or an actual second determiner (24 — these
want checking). So: the relation `la → via` is an edge at *Inf* 1:3 and is
absent at *Inf* 1:1, and the only difference is that a contraction happened.
This holds under enumeration too: without the split, `il` cannot be a member
of the phrase it determines. The terminal decomposition is motivated
independently of what is built above it.

The tail of the composite-POS inventory also contains spacing variants
(`verb + pronoun` 2, `preposition + article` 1) — Layer-2 hygiene rather than
a design matter, but it belongs on the list.

### What L2 does and does not renumber

Old Layers 1–5 keep the addressing they already have; nothing in the design
edits `dep/`, `np/`, `skel/`, or `case/` in place. L2's split is not a second
blind renumbering on top of L1: every L2 entry carries the `l1_index` it came
from, so the old-to-new correspondence is data, not something a consumer has
to reconstruct.

### Bootstrap status (premise 3)

Old Layer 2's composite-POS and lemma columns are used once, as bootstrap
precedent for building and checking the split/POS/normalization tables
(premise 3) — never as an input the running L2 pipeline reads. The three
passes read L1 and, per step, each other's own prior-step output; no
generation-2 definition names an old-generation file.

## Rollout plan (operator, 2026-09-09)

**Canto 1 first, starting at *Inf* 1:1-9 and widening gradually, before any
pass runs corpus-wide.** Every measurement above was corpus-wide from the
start, but running the three-step pipeline itself corpus-wide first would
repeat the mistake premise-checking exists to avoid: 442 + ~1,686 wordforms
is enough surface area that a systematic prompt or pipeline-ordering error
could pass a spot check and still be wrong at scale. `reads/inf-1-1-9.md`
already established the same discipline for reading — nine lines, findings
measured corpus-wide only *after* being seen concretely — and the
split/POS/normalize build should follow it rather than start from the
opposite end. Concretely: run all three passes over *Inf* 1:1-9 only,
hand-inspect every wordform's split, POS, and normalization against the
source (the *Inf* 1:1 and 1:25 worked examples above are the first two data
points), widen to the rest of *Inf* 1 (136 lines), only then the full
corpus.

## Implementation: step 1 only (`gen2/l2.py`, 2026-09-09)

**Scope: the split. Steps 2 and 3 are not implemented** (operator: 「まず単語の
分解だけ実装してください」). `gen2/l2.py` assigns no POS and restores no
spelling — `ch'` stays `ch'`, `i'` stays `i'`, `cammin` stays `cammin`.

**One decision this file had to settle first.** *Execution mechanism* above
puts old Layer 2's row in $O$ as bootstrap precedent; *The concrete task*
says build "with no view of old Layer 2", then diff. **The second is
adopted** (operator, 2026-09-09): agreement with `morph/` has to be evidence,
not an echo of having been shown the answer. The model sees the passage and
its tokens and nothing else; old Layer 2 enters once, afterwards and offline,
through `--check`.

**Granularity is old Layer 2's** — `--chunk`, default 3 lines per request,
matching `morph/morph.py --chunk 3` — per the correction recorded under
*Execution mechanism* above. Over *Inf* 1:1-9 that is **3 requests, not 56**.

The pieces:

- **`L2Entry(l1_index, text)`**, **`L2Line(no, entries)`** — frozen
  dataclasses with `to_dict()`, mirroring L1's shape. The L2 token number is
  the position in `entries`; only `l1_index` is data, as designed.
- **`is_splittable(token)`** — a token with no letter never splits, so
  punctuation costs no model call. This is a deterministic reading of L1's
  own output, not a fact borrowed from old Layer 2.
- **`chunks(lines, size)` / `asked_tokens(chunk)`** — the unit of work, and
  the chunk's splittable tokens in L1 order. `chunks` is `morph.py::_chunks`.
- **`apply_splits(line, splits) -> L2Line`** — the pure half. `splits` is
  keyed by position, `(line number, l1_index)`. A token with no split passes
  through verbatim, casing and apostrophe kept, which is also what an
  *unanswered* token gets: a failed step degrades to the identity, never to a
  hole in the line.
- **`ask_message(chunk, refusal="")`** — $O$: `<lines>` for context,
  `<tokens>` to fix the boundaries, `<verdict>` saying which of the two
  situations this is.
- **`locate_key(key, tokens)`** — which token a row's key names. One token, or
  a run of consecutive tokens **ending with** the one being split. A key
  matching two places is refused with both lines named, rather than applied to
  both — those two places are exactly where a wordform can split two ways.
- **`parse_split_answer(text, tokens) -> (splits, error)`** — the runtime
  gate: exactly one `<split>` block, **only rows for tokens that split**, each
  key resolving to exactly one token, each value 2-3 non-empty whitespace-free
  parts. A row restating a token unchanged, a token named twice, or a key that
  is not a run of this passage's tokens refuses the whole answer. An empty
  block is a valid answer meaning "nothing here splits".
- **`split_chunk(...) -> ChunkResult`** — the bounded step. Every attempt
  calls `generate.reset()` and sends exactly `[system, user]`, so no
  transcript crosses a chunk *or a retry*; a refused attempt records nothing
  and re-asks with the reason (`harness/stages/09.md` §2.1's "refusal is the
  identity morphism"). Budget 3, a cost cap. Acceptance is `accepted`, a fact
  about the gate — never `bool(answers)`, since "nothing splits here" is a
  settled answer.
- **`build_splits(...) -> dict[(line, l1_index), parts]`** — one step per
  chunk; a group that never passes is **retried line by line**; each
  occurrence keeps its own reading, and a wordform answered differently from
  its first reading is recorded as a conflict. `on_settled` streams each
  chunk's record to the log sink as it settles.
- **`render_artifact` / `parse_artifact` / `artifact_path`** — the TSV, `line
  l1_index l2_index text`, written to `layers/l2/<canticle>/NN.tsv`, the
  shape every other layer in this repository already uses. **`gen2/` is a
  code directory: no artifact and no run log is written into it** (operator,
  2026-09-09). `l2_index` is written down because a flat file has no order to
  lean on; it is derived from the entry's position, not decided.
- **`check_against_precedent(l1_lines, l2_lines, morph_rows)`** — the offline
  diff, wordform by wordform for the `L2`/`old Layer 2` columns shown (the
  table's `ours` column was renamed to `L2` — operator, 2026-09-09: this
  artifact is called L2 elsewhere in this document and should be here too).
  Old Layer 2's split is read off the `lemma` column (`+` means composite; a
  non-composite row's lemma is a lemma, not a split, so the wordform stands
  for itself), and `our_splits`/`precedent_splits` each keep every distinct
  reading a wordform has, never collapsed to a majority. **The verdict
  (`agrees` / `differs` / `l2-ambiguous` / `layer2-ambiguous` / `absent`),
  corrected three times on 2026-09-09, checks three independent things, in
  order:**
  1. **`l2-ambiguous` is a property of this artifact alone.** This wordform's
     own readings, case-folded so `A`/`a` never count as two, are genuinely
     distinct somewhere in `line_range` — independent of whether either
     reading agrees with old Layer 2 at its own position. A wordform this
     artifact correctly reads two different ways in two different contexts
     (`nel` = `in+il` here, `ne+lo` there, both right) is `l2-ambiguous` even
     where old Layer 2 agrees with both — the first cut of this rule made it
     require a positional disagreement too, which made it impossible for a
     *correct* internal distinction to ever surface (it would always be
     swallowed into `agrees`); that ordering is what this correction removed.
  2. **`layer2-ambiguous` is the symmetric property of old Layer 2 alone**,
     checked next: old Layer 2's own readings for the wordform, case-folded
     the same way, are genuinely distinct within `line_range` — a real
     disagreement old Layer 2 has with itself, kept as its own outcome rather
     than folded into `differs`. Distinct from the case this document earlier
     ruled out (a synthetic scenario where old Layer 2 records two things at
     a line this artifact never processed at all): here both readings are
     within the range this run actually asked about.
  3. **Otherwise, `differs` is gated by `_positionally_mismatched_wordforms`**:
     neither side is internally ambiguous, but at least one occurrence
     disagrees with old Layer 2 *at that exact position* — the same pairing
     `render_check_lines` marks with `[...]`, this line's `n`-th splittable
     L1 token against old Layer 2's `n`-th row for the line. A wordform whose
     only "disagreement" is that it reads `A` at one position and `a` at
     another — each agreeing with old Layer 2 where it occurs — is `agrees`,
     not `differs`.

  Which of L2.md's two non-agreement outcomes a `differs` row is remains a
  judgment recorded here, not something the checker decides.
- **`render_check_lines(l1_lines, l2_lines, morph_rows)`** — added
  2026-09-09, a per-line view of the same positional pairing: reconstructs
  each source line as a plain `" ".join()` (punctuation untouched) and prints
  only the lines carrying at least one mismatch, `word(parts)` for this
  artifact's own split and `[...]` appended with old Layer 2's reading at
  that exact position when it disagrees. No case-folding (a genuine case
  difference is a difference) and no aggregation across occurrences — pure
  position, uniformly, first occurrence or not.
- **`_run_check`'s report, restructured 2026-09-09 (operator: 「差異があれば
  種類に応じて…混ぜない」).** Prints `render_check_lines`'s per-line view
  first, then three separate sections rather than one flat table —
  `[differs]` (a `wordform` / `L2` / `old Layer 2` table, one row each,

## Is a `differs` random or systematic? A three-run check (operator, 2026-09-09)

A single run cannot tell a stochastic slip from a repeatable mistake — with
one answer, "the model got this wrong" is all that is knowable. **Two more
full runs of *Inf* 1** were generated with the same model and prompt,
`-o layers/l2/inferno/01-2.tsv` and `-o layers/l2/inferno/01-3.tsv` (the
`-o`/`-l` short flags for `--out`/`--lines` were added to `gen2/l2.py` for
this), alongside the original `01.tsv` — three independent answers to
diff against each other, not against old Layer 2. Two outcomes are
possible per position, and both occurred:

- **All three agree, and it's still wrong — `pel` (*Inf* 1:33).** `01.tsv`,
  `01-2.tsv`, and `01-3.tsv` all split it `per+il`. Three independent runs
  landing on the identical wrong answer is exactly the signature of a
  **systematic** error, not a stochastic one: the model has no way, from
  one chunk of lines, to know that `pel` is `pelo` (fur) in all 7
  corpus-wide occurrences and never a contraction. **A majority vote over
  more runs would not have caught this** — there is no minority to
  outvote. This confirms the diagnosis and closes the open question of
  whether `pel` was a fluke: it is not.
- **The three runs split, and majority is not a reliable verdict.** Exactly
  two other positions disagree across the three files:
  - *Inf* 1:17 `de'` — `01.tsv` and `01-2.tsv` split it `di+i` (matching old
    Layer 2's `preposition+article`, `morph/inferno/01.tsv:126`); `01-3.tsv`
    alone leaves it whole. **Majority is right here**: 2/3 agree with the
    precedent, and the lone dissenter is the error.
  - *Inf* 1:111 `dipartilla` (verb half) — `01.tsv` and `01-3.tsv` both read
    `diparta` (present subjunctive); `01-2.tsv` alone reads `dipartì`. Old
    Layer 2 records this token as **remote past** (`morph/inferno/01.tsv:808`,
    `dipartire+la`), which is `dipartì`, not `diparta`. **Majority is wrong
    here**: two independent runs converged on the same incorrect verb form,
    and the correct answer is the one-vote minority.

**The conclusion, stated plainly: majority vote across repeated runs is a
detector for disagreement, not a verdict on correctness.** It reliably
finds the positions worth looking at — three-way agreement does not (`pel`
proves that), and three-way disagreement is a real signal even when the
majority itself is the error (`dipartilla` proves that too). Every
disagreement still has to be argued from precedent (old Layer 2's own
data here, per the standing methodology), never settled by vote count
alone. `l2/CORRECTIONS.md`'s first entries, once written, are these three:
`pel` (mechanism problem, unresolved — see below), `de'` at 1:17 (`01-3`'s
miss corrected against the 2/3 + precedent agreement), and `dipartilla` at
1:111 (`01.tsv`'s and `01-3.tsv`'s shared error corrected against `01-2`'s
minority reading plus old Layer 2's `remote past` feature).

## Step 0: restoring dropped letters before the split (operator, 2026-09-09)

**The argument that produced this pass.** Old Layer 2 got `pel` right, and
`morph/morph.py`'s prompt says why: it never asks whether a token splits. It
asks for a lemma, a part of speech, a gender and a number **in one row**, so
writing `pel` as `per+il` would also mean writing `preposition+article` at that
position, and `di` + a preposition-article is unwritable in
`che di pel macolato era coverta`. **The wrong answer was blocked by a second,
contentful column**, not by better knowledge. Step 1, asking only about shape,
has no such column — which is exactly why three independent runs all split
`pel` the same wrong way.

Two ways to put that mechanism back were identified. One is to let **step 2
revoke a step-1 split** when no coherent POS sequence exists for the parts in
the line. The other, taken here, is to ask the contentful question **first**,
and as the question a language model answers most directly: *what word is
this?* — a choice of word form rather than a classification (operator: the
model is not reliably conscious of parts of speech; it selects word forms
statistically, so choosing the form first may be the more accurate order). A
token restored to `pelo` is never offered the trap, because `pelo` is not
`del`-shaped.

**Restoration is needed at both ends of the split, not only before it.** A
fused token can hide a truncation *inside* it: `farne` is `far`+`ne` and `far`
is `fare` shortened, visible only once the token is split — the corpus has
`farsi` 8, `farne` 3, `farmi` 3, `dirne` 2, `udirti` 2, `vederti`, `vedervi`,
… all of this shape. So this pass does not replace step 3; it is a second
instance of the same operation at the other end, and each catches what the
other cannot:

    before the split   a truncation masquerading as a fusion      (the pel case)
    after the split    a truncation hidden inside a fusion        far+ne -> fare+ne

### The scope is stated as an operation on letters, never as "the standard form"

Calling it alignment to a standard invites lexical substitution, and most of
what looks archaic here is not a shortened word at all — modern Italian
descends from this language, so `sanza`, `core`, `giuso` are simply its words
(operator, 2026-09-09). Only two things are restored: **the letters an
apostrophe stands for**, and **a final syllable dropped with no apostrophe**.

**The apostrophe marks *where* the letters go, and is read as a marker rather
than stripped** (operator). Stripping it and asking only that the token's
letters read through the answer is not enough — it does not say which end grew,
and would accept a leading restoration on a token whose apostrophe is at the
end. So `is_restoration` requires, mechanically:

- the token's own letters read straight through the answer, unbroken and in
  order (this is what refuses a respelling: `sanza` -> `senza` would have to
  turn `a` into `e`);
- a **trailing** apostrophe: the answer grows at the end;
- a **leading** apostrophe: the answer grows at the beginning;
- **no** apostrophe: the answer grows at the end only.

A rule this shape needs no list of forbidden words, which is what keeps the
pass off lexical substitution by construction rather than by exhortation.

### A discipline, recorded because it was broken first

**A wordform under measurement must not appear in the prompt.** The first
version of this pass's prompt used `pel` -> `pelo` as its worked example of the
apocope case, and an early probe duly restored it. Removing that one line, the
same model on the same passage left `pel` untouched. **Steering a one-shot to
the answer and hand-correcting the answer afterwards are the same act**
(operator), so an experiment whose prompt contains its own answer measures
nothing.

The prompt was then stripped of **every** example, Italian word and worked

### Implementation (`gen2/restore.py`, `gen2/skills/l2-restore/`)

The machinery is step 1's, deliberately: the same chunk of lines per request
(`--chunk`, default 3), answers keyed by the word and never by an index, no
transcript across a chunk or a retry, the gate in the runtime, refusal as the
identity, a line-by-line fallback when a group never passes, resume off the
artifact, and the append-only log. `l2.py`'s own primitives (`Asked`,
`locate_key`, `chunks`, `is_splittable`) are imported rather than copied, so
the two passes cannot drift on what a token is or on how a key names one.

The artifact is `layers/l2/<canticle>/NN-restore.tsv`, one row per L1 token
with the restored form beside it — **every** token, not only the changed ones,
so the file records what was considered and a run can resume off it.

**`l2.py -r <that file>` is how the split consumes it, and it moves only the
question.** Each token is *asked about* in its restored spelling; positions are
unchanged, and `apply_splits` still writes the L1 surface for every token that
does not split. So an imperfect restoration cannot pollute the split artifact,
and restoring an entry's spelling remains step 3's. The verse is quoted as
written while the token list is not, so the request names that difference in a
`<note>` block rather than leaving the model to notice and "correct" it.

Tests: `layers/tests/test_gen2_restore.py`, 42 (121 with L1's and step 1's,
`uv run pytest layers/tests`).

### What this settles

**The pass works as normalization and not as a guard for the split.** Its
output is real step-3 material — 136 restorations, per-occurrence `l'`, correct
aphaeresis, a gate that refuses respellings — and the position it was placed at
is the one thing it did not earn: 6.2x the cost of the split pass, no change at
`pel`, and its one changed position reached by another run without it.

Moved to *after* the split, this is the pass the `far`+`ne` shape needs anyway.

**The `pel` question therefore returns to the other candidate: step 2 revoking
a step-1 split.** What made old Layer 2 right was a second column contradicting
the wrong answer *at the same position*; a restoration pass is still one
question about one token in isolation, and it turned out not to carry that
contradiction. A POS pass reading the parts **in the line** does. Its cost —
a backward edge from step 2 to step 1, against `L2.md`'s otherwise one-way
pipeline — is bounded if the revision runs once, step 1 is not re-run after it,
and each revision is recorded as its own event, so every artifact position
stays attributable to a named pass.

## Split and POS become one pass (operator, 2026-09-09)

**The argument, and it is not the experiment's.** Once a token is written down
as `per`+`il`, the route back to `pelo` is closed: every later pass meets two
grammatical words, not the trap. So the guard cannot be a pass that runs after
the split, and — measured over the whole canto — it is not a pass that runs
before it either (*Step 0*, above). What is left is the position old Layer 2
occupied: **ask the contentful question at the same position, in the same
answer**. `morph/morph.py` never asked whether a token splits; it asked for a
whole row, and at *Inf* 1:33 `che di pel macolato era coverta` the wrong split
is unwritable because the row it forces — `di` preposition, `per` preposition,
`il` article — puts two prepositions and an article in a row and leaves
`macolato` with no noun to agree with. The line contradicts it. A shape
question has nothing to contradict.

**Lemmas are excluded** (operator). Old Layer 2 carried the guard in `lemma`,
but the POS column alone is enough to make `di per il macolato` unwritable, and
the lemma column brings what this layer does not want: a dictionary judgment,
which is exactly what splits one wordform's rows between an adjective form and
a verb infinitive (`REDESIGN.md` §6, `smarrito` 4/4), and the "standard form"
framing already rejected for `sanza`/`core`/`giuso`. The guard is kept, the
lexicon is not.

**Restorations are not excluded, and that subsumes step 3** (operator,
2026-09-09: 「ben→bene 禁止する必要はないのでは？restoreを包含しているので」).
The first version of this gate demanded a single word be the token *verbatim*,
which refuses `ben` -> `bene` — but that is a restoration, not a lemma, and the
distinction is already mechanical: `is_restoration` (moved here from
`restore.py`, which now imports it) requires the token's own letters to read
straight through the answer, growing only at an end the token's own spelling
opens. So `ben` -> `bene`, `ch'` -> `che`, `'l` -> `il` pass, while `sanza` ->
`senza`, `smarrita` -> `smarrito` and `era` -> `essere` are refused — gender,
number, tense and mood cannot move, which is what "no lemma" was protecting.

Two consequences. **The `far`+`ne` shape becomes reachable in this pass**: the
parts are written whole, so `farne` is `fare`+`ne` — the truncation hidden
inside a fusion, the one case *Which order* proved no separate pass could reach
from before the split, and the only remaining job `restore.py` had. And **the
answer now carries all three decisions at once** — split, tag, restored form —
so the entries this pass writes are already step 3's output rather than input
to it.

**Coarse only, one stage.** *Step 2 should be staged* stands: the tag set is a
closed ten — `noun verb adjective adverb pronoun preposition article
conjunction numeral interjection` — with subtypes (`proper noun`, `relative
pronoun`) and features (gender, number, person, tense, mood) left to a later
stage over these entries. Old Layer 2's 39-value drift is what an open column
produces. The participle convention that section asked for is stated in the
prompt as a convention, not left to the passage: **a participle is `verb`**,
predicative or attributive.

**What changed mechanically** (`gen2/l2.py`, replacing the split-only module;
`gen2/skills/l2-words/`, replacing `l2-split/`):

| | split-only pass | this pass |
|---|---|---|
| answer | one `<split>` block, **differences only** | one `<table>` block, a Markdown table, **one row per token** |
| question | the verse, then a flat list of tokens | the verse, then **the answer table with its first two columns already filled in** |
| row | `key:part+part`, key naming a unique place | `\| Line \| Index \| Token \| Words \| Part of Speech \|`, matched **by position** |
| silence | a token with no row is a single word | impossible — a missing row is a refused answer |
| a word's spelling | the L1 surface, untouched | the whole word, dropped letters put back (`is_restoration` bounds it) |
| artifact | `line, l1_index, l2_index, text` | `line, l1_index, l2_index, text, pos` |
| `--check` | splits, off old Layer 2's `lemma` | splits (restoration-tolerant), **plus** `[restored]`, **plus** tags off its `pos` through `COARSE_POS` |

Two things follow from the dense contract. The proof the split-only design
gave up — that the model produced a judgment for every token — **comes back**:
`pel` can no longer pass by silence, it has to be tagged in the line. And keys
disappear entirely, with them `locate_key` and the whole "name the occurrence
uniquely" apparatus (it moves to `restore.py`, now its only user): row *n*
answers token *n*, so a wordform occurring twice in a chunk simply takes two
rows and needs no disambiguation.

**The question hands over the table to fill in** (operator, 2026-09-09: 表だけだと
transformer がうまく文章のイメージを構築できない可能性がある). The verse was
always shown; what was weak is that the tokens then arrived as a flat list with
the line boundaries stripped out, which is exactly the context `pel` needs.
`render_blank_table` sends the answer's own table instead, `Line` and `Token`
filled in and the last two columns empty:

```
<table>
| Line | Index | Token | Words | Part of Speech |
|---|---|---|---|---|
| 33 | 1 | che |  |  |
| 33 | 2 | di |  |  |
| 33 | 3 | pel |  |  |
| 33 | 4 | macolato |  |  |
</table>
```

Three things follow. **The line number rides on every row**, so no row is ever
adrift from the verse it belongs to. **The row set stops being something to
reconstruct** — the answer is a fill-in, so a dropped or added row is a visible
edit rather than a miscount, and the gate checks the `Line` column too (a
disagreement means rows moved). And the shape of the answer needs no
describing, because it is the shape of the question. The prompt also asks, in
words, that the passage be read as verse before anything is filled in.

**Question and answer are one block under one name** (operator, 2026-09-09).
The first version of this pass sent the table out as `<tokens>` and took it back
as `<words>`, which contradicts the paragraph above: two names say two things are
being carried when it is the same table travelling in both directions, and
`<words>` additionally reads as the name of one *column*. Both ends are now
`<table>` — the answer is literally the block the question handed over, with its
two blank columns filled — and the prompt's instruction is the same sentence.
The one thing the shared name costs is that a model quoting the question's own
table inside its prose would trip the two-block refusal; the gate's message names
that case explicitly, so it is fed back as a repair rather than a puzzle.

### `Index`, and the readout that had to be regrouped

Two corrections came out of reading that run (operator, 2026-09-10).

**The table gained an `Index` column, filled in by the question.** Every refusal
this gate writes names a `row N` — five of this run's six did — and that number
existed only inside the program, so the model had to count to find the row it
was being asked to repair. `Index` hands it over. It is the row's own number,
1-based over the rows listed, and **it is not the artifact's `l1_index`**, which
is 0-based and counts the punctuation the table leaves out; positions in the
artifact are still attached by the program, and the model copies this column
like `Line` and `Token` rather than computing one. The gate checks it before
reading any content, so a gap or a repeat is caught as what it is.

What it does **not** do is prevent omissions, because this run had none — the
honest claim is that it makes the refusals that do happen cheaper to repair. Nor
does it reach the one shape nothing currently catches: two occurrences of the
same token *within one line* whose answers are swapped would match on `Line`,
`Index` and `Token` alike.

**`TWO READINGS` is kept and regrouped.** It is this pass's only intrinsic check
— it consults no other layer, which is what `PLAN.md` §3.1 asks of the successor
to the lost progress metric and what premise 3 requires at rebuild time — and
over *Inf* 1 it independently surfaced `via`, `tutte`, `poco` and `alto`, three
of which `--check` also flags against old Layer 2. But printed per occurrence it
was 76 lines for those four words. Two changes, and the answer was already on
disk in the checker's own history: fold capitalisation out of the comparison
(`Analysis.reading`; a line-initial `Io` against a mid-line `io` is one reading,
and this alone was 22 of the 76 — the same case-fold artifact the `--check`
rework removed once already), and report **one line per wordform with counts**
rather than one per hit, the shape `[L2 ambiguous]` settled on for this reason.
The same run's data now reads as **17 lines**:

```
[two readings]  (17 wordform(s) this artifact read more than one way; every reading stands)
  che           che (conjunction) x18, che (pronoun) x18
  l'            le (article) x10, la (article) x4, lo (article) x4, la (pronoun) x1, ...
  poco          poco (adverb) x3, poco (noun) x3
  via           via (adverb) x1, via (noun) x1
  ...
```

`che` at the head is the finding B alternation, not an error; `via` and `poco`
are. Which a line is remains a judgment for this document, not for the report.

### The eleventh tag, declined — and the convention given its reason

Two runs left the participle convention being applied at nine positions and declined at
two, so the question could not stay open. It is **decided against an eleventh tag**
(operator, 2026-09-10), and the argument is old Layer 2's own numbers rather than a
preference.

`REDESIGN.md` §6 counted three incompatible encodings of the participle. Re-derived here
directly, they are not three equal thirds — the column matters:

| encoding | rows |
|---|---:|
| `pos=verb`, participle recorded in the **`tense`** column | **722** |
| `pos=participle` / `pos=past participle` — participle in the **`pos`** column | **31** |
| `pos=adjective` at a participle form | 573+ (§6's defect) |

**722 against 31 is 23:1, and it settles the shape of the fix.** §6's finding is that
the corpus says three things at once; the repair is to pick one, and the one the corpus
overwhelmingly already uses puts participle-hood in a *feature* column beside `pos=verb`.
An eleventh tag would build the 31-row minority into generation 2's design.

The same conclusion follows from this pass's own stated boundary, which it would
otherwise cross: *finer distinctions — gender, number, person, **tense**, mood, and the
subtypes of each category — are a later pass's*. In this corpus a participle **is** a
value of `tense`. `numeral` is not a counter-example: a number word is a lexical class,
not an inflection of one.

And the tag column's designed job does not need the distinction. What makes `per`+`il`
unwritable at *Inf* 1:33 is that it puts two prepositions and an article in a row and
leaves `macolato` with no noun — a fact about categories in sequence. Whether `macolato`
is a participle or an adjective changes nothing there.

**The cost of adding it is concrete**: a new participle-versus-adjective judgment, asked
at exactly the lexicalised positions — attributive, nothing verbal nearby — which is the
boundary that produced the 573-row `adjective` bucket in the first place. That is §6's
defect being re-opened under a new name, not closed.

**What is done instead: the convention is given its reason.** The prompt had stated it as
a bare prohibition (*do not retag a participle `adjective` because it reads like one
here*), and a model that reads `li antichi spiriti dolenti` as an adjective phrase — it
is one — has nothing to weigh the prohibition against. The reason is now stated: the
later pass can add *participle* to a `verb`, but it cannot recover a verb from an
`adjective`, because nothing in the row would say a verb had ever been there. So
`adjective` at a participle does not record a finer judgment, it destroys a coarse one.

**This is a testable change, and the test is the next run.** The wordforms under
measurement are deliberately absent from the new prompt text — the discipline this
document records from the `pel` → `pelo` incident — so 1:115 and 1:116 answer it
honestly. If they come back `verb` the reason reached the model; if they come back
`adjective` the convention needs a mechanism rather than better prose, and the eleventh
tag returns to the table on different grounds than the ones declined here.

**The check reads all three decisions, each on its own grain.** Splits are
compared by `readings_agree` — same number of words, each identical or one
side's restoration of the other — so `dei` against old Layer 2's `de'` is
agreement about the split, and only a different split is a `differs`. A token
that stayed one word is folded back to the token in `our_splits`, or every
restored wordform would read as `l2-ambiguous` and bury the split findings.
Restorations get their own `[restored]` section (per-wordform, with counts),
and the run's summary counts them beside the splits.

**The POS half of `--check`.** Only positions where both sides split the token
the same way are compared — where the splits differ the tags describe different
words, and counting that twice would inflate one finding into two. Old Layer
2's tag is folded through `COARSE_POS` first (`proper noun` -> `noun`,
`relative pronoun` -> `pronoun`, `past participle` -> `verb`, `preposition+article`
-> two tags), so only a real difference of category is reported, with its line
and word. Anything with no coarse equivalent is left as written rather than
folded silently. Verified offline by feeding the checker old Layer 2's own rows
as the artifact (68 of 68 positions agree, 56 wordforms agree) and then
perturbing one tag, which the `[pos differs]` section reports at its position.
Feeding it the same rows with old Layer 2's `apocope` lemmas substituted, the
six restorations in 1:1-9 (`ben`, `cammin`, `dir`, `pensier`, `qual`,
`trattar`) list under `[restored]` and the split table stays 56 agrees / 0

**What this costs, unmeasured.** The answer is now dense — 68 rows for nine
lines where the split-only pass sent four — so output tokens per request rise
by roughly the token count, against an input prompt that is barely changed.
Whether that lands near the split's 14.5 min per canto or nearer step 0's 89 is
not known until it runs. Two forces pull opposite ways: the tag column is
recognition over a closed set, which *Step 0* identified as the cheap half,
while the restored spelling is the open generation it identified as the
expensive one — but it is now asked in the same request as everything else,
rather than as a second pass over every token, and step 0's 89 minutes bought

## What is still open

- **Widening.** *Inf* 1 (136 lines) is done. The rollout plan's next rung is
  the rest of the corpus. This run exercised both things 1:1-9 could not:
  clitic compounds (6 of them, all split correctly at the surface level) and
  the differences-only blind spot (`--check` had something to say, and one of
  its two genuine `differs` was a real model error).
- **`pel`'s failure mode: the mechanism is built, and untried against it.**
  The three-run check confirms it is systematic; step 0 (restore-before-split)
  was built, run over the whole canto and did not catch it; the split and the
  coarse POS are now one answer, which is the position old Layer 2's guard
  actually occupied (*Split and POS become one pass*). **Whether it catches
  `pel` is unmeasured** — no live run of the merged pass has happened. That is
  the first thing to find out, and *Inf* 1:33 is the position to read.
  `l2/CORRECTIONS.md` records the fact of the error either way.
- **`l2/CORRECTIONS.md` not yet written.** Adopted in principle (see above,
  operator 2026-09-09); the file itself, with its first three entries
  (`pel`, `de'` at 1:17, `dipartilla` at 1:111), is still to be created.
- **The differences-only contract is gone**, and with it its blind spot: the
  answer is one row per token again (*Split and POS become one pass*). What
  the earlier measurement showed — one real miss out of 511 wordforms under
  the sparse contract — is now history rather than a standing risk.
- **The artifacts on disk predate the merged pass.** `01.tsv` and the three
  diagnostic runs `01-2`/`01-3`/`01-4` are four-column, split-only files; the
  new reader treats a four-column file as holding nothing, so a run over them
  asks from the first line rather than resuming into a shape with no `pos`.
  Their disposition is still the undecided question below.
- **Step 3 is folded into the pass, and `gen2/restore.py` is left with no
  job.** Restoring dropped letters is now one of the three things the answer
  decides, per part, which reaches the `far`+`ne` shape a separate pass could
  not; the cases that motivated the step-2-then-step-3 ordering (`l'` ->
  `lo`/`la`, the 159 cross-POS wordforms) are decided in the same answer as
  the tag that disambiguates them, rather than after it. `restore.py` and its
  artifact stay on disk — measured work, and `is_restoration` now lives in
  `l2.py` where both use it — but nothing runs it, and whether it is deleted
  is undecided. What is *not* settled is whether one answer decides all three
  as well as three answers would: unmeasured until a live run.
- **Build order.** L4 (dependency) precedes L3 (phrases) in the rebuilt
  stack despite the numbering — L3 must project from generation 2's own L4,
  never from old Layer 4 (`REDESIGN.md` §5). This does not block L2, which
  only depends on L1.
- **The bootstrap safe/contaminated split** for everything past L1 — which
  frozen layers are a safe one-time warm start and which are contaminated
  positions the model must not anchor to — is discussed but not settled
  (`PLAN.md`'s *Still deferred* note). Load-bearing for L2's POS-classification
  step specifically (old Layer 2's `pos` vocabulary is one of the named
  contaminated candidates), irrelevant to the split table itself (closed
  vocabulary, no model call needed there beyond flagged exceptions).
