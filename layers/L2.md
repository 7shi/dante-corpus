# L2: grammatical words, split from L1

Everything `PLAN.md` and `REDESIGN.md` say about generation 2's Layer 2,
gathered in one place, the same way [`L1.md`](L1.md) gathers L1. **L2 is
designed but not implemented** — no `gen2/l2.py`, no rollout run yet.

## What old Layer 2 gets wrong

`PLAN.md`'s handoff (old Layer 2 review, `REDESIGN.md` §6, entry point *Inf*
1:3 `smarrita`): past participles are encoded three incompatible ways
(`pos=verb`+`mood=participle` 724 / standalone `pos=participle` 25 /
`pos=adjective` 573+, the last splitting its own lemma between the adjective
form and the verb infinitive for 104 wordforms; `smarrito` itself splits 4/4).
The `pos` column holds 39 values, not a closed set — subtype leakage
(`relative pronoun`/`pronoun`, `proper noun`/`noun`) plus spacing duplicates
and singletons. Checked against `case/`: `case/` is complete and closed
(13,157 rows, exact match), so the sparseness is not a `case/` coverage gap —
it is a pass-through of Layer 2's `pos` column read verbatim
(`case/case.py:11`), meaning a mistagged `pos` (e.g. a `che` mistagged
`conjunction`, finding B's 225 positions in `reads/inf-1-1-9.md`) never
reaches `case/`'s build step at all. Recorded correction: the working
assumption that "later layers don't lean heavily on `pos`" does not hold for
`case/` specifically.

Also relevant to L2's scope: old Layer 3's fused-enclitic-pronoun mechanism
(`clitic_mentions()`, the `"+lemma"` sentinel span, e.g. *Inf* 1:59
`venendomi` → `np/inferno/01.tsv:59` `+mi`) compensates for old Layer 1 having
no position for a bound pronoun. L2's split table covers exactly this shape
(`verb+pronoun`, 488 tokens / 372 wordforms), so under the rebuilt stack the
pronoun becomes an ordinary L2 entry and the whole synthetic-mention
apparatus has nothing left to compensate for (`REDESIGN.md` §2.2).

## The design (`REDESIGN.md` §2.1)

**L2 splits contractions and clitic compounds into their grammatical words,
and carries a back-reference to the L1 token it came from.** Under premise 3
this is generation 2's own step, not a lookup into old Layer 2's lemma
field — but it is also **independent of grammatical analysis** (operator,
2026-09-09), kept out of the POS-tagging/dependency pass entirely, so a
mistake in one is never entangled with a mistake in the other.

L2 is an **ordered list of `(l1_index, text)` pairs** — the L2 token number is
its position in that list and is never stored separately, only `l1_index` is
data. A composite L1 token produces **several** L2 entries sharing one
`l1_index` (1:many); every other L1 token, including punctuation, carries
straight through as exactly one L2 entry (1:1). Worked example, *Inf* 1:1
`Nel mezzo del cammin di nostra vita`:

```
L1   0:Nel  1:mezzo  2:del  3:cammin  4:di  5:nostra  6:vita
L2   (0,in) (0,il) (1,mezzo) (2,di) (2,il) (3,cammin) (4,di) (5,nostra) (6,vita)
```

`Nel` (L1 index 0) and `del` (L1 index 2) each yield two L2 entries; every
other L1 token yields one. Nothing downstream that needs the original token
(old Layer 4's `head_line`/`head_token`, say) loses the ability to name it.

### The split table

Old Layer 2's 2,681 composite-POS tokens reduce to **442 distinct wordforms**
(case-folded) — `del` 569, `al` 549, `nel` 310, `dal` 172, `col` 109, … — and
**423 of 442 (95.7%) have exactly one recorded split**, with no dependence on
the sentence around them. Only 19 show more than one, mostly old Layer 2's
own spelling noise on the same lemma (`dimmi` as `dire+me` / `dire+mi`)
rather than real ambiguity; `dal` showing both `da+il` and `di+il` is very
likely an outright error (`dal` is not a form of `di`), while `nel` genuinely
splits two ways (`in+il` the ordinary contraction vs. `ne+lo` the pronoun
compound) — real but rare. **L2 is therefore a static lookup table plus a
handful of flagged exceptions, structurally the same device `tokenizer.py`'s
`quote_cases.txt` already is for apostrophe normalization** — not a
grammatical judgement, and not an LLM call. Old Layer 2's decomposition data
is precedent for building and checking that table, not an input the running
split reads.

### L2 only splits; it never merges (operator, 2026-09-09)

`l1_index` is always a single integer, never a tuple — so a many:1 direction
(several L1 tokens = one grammatical word) is not a shape L2 takes, even
though the corpus already has that phenomenon: old Layer 4's `fixed`
relation, **170 groups**, almost all complex prepositions (`in su`, `dietro
a`, `presso a`, `per entro`, …), 169 of size 2 and one of size 3 (*Par*
32:133 `Di contr'a`), every one contiguous. Merging was tried at this level
and measured to conflict with splitting: **37 of 170 fixed groups (21.8%)
have a member that is itself a composite-POS token**. *Inf* 7:130 is the
clean case —

```
130:7  al = a+il  (preposition+article), fixed head
130:8  da          (preposition),        fixed child
```

— the multiword expression is `a da` ("at last"), not `al da`: only the `a`
half of `al` participates, `il` does not. A tuple `l1_index` naming both L1
tokens would claim `il` belongs to the fixed group, which is false.
Decomposition must go all the way down first — every token split to its
finest grammatical-word grain — before anything is put back together. **The
merge stays exactly where the corpus already puts it: a `fixed`-style edge
one layer up (L4, over L2 entries), not a second, conflicting join built
into L2 itself.** L4 gets this cheaply for the 133 non-conflicting groups and
correctly for the 37 conflicting ones, because at the L2 level `a` and `il`
are already two separate, addressable entries and the edge can point at
exactly `a`.

### Normalization: apocope and elision, to the surface form (operator, 2026-09-09)

`i'` is `io` with its final vowel restored, and that stops at `io`; it does
not continue on to a lemma, because for this wordform they happen to
coincide. They do not always: `son` restores to `sono`, and `essere` stays
where it already is, as the lemma a later, independent pass assigns. Measured
over old Layer 2's `apocope`/`elision`-noted, non-composite rows:

```
apostrophe-marked   (l', 'l, ch', d', s', m', t', 'n, com', i', …)   300 wordforms   7,047 tokens
no apostrophe       (son, eran, avea, vuol, gran, cor, tal, …)     1,386 wordforms   6,909 tokens
```

The apostrophe-marked set is exactly as clean as the split table — the
boundary is visible, restoration is one vowel, and the lemma is usually the
same closed-class word anyway. The no-apostrophe set is not: **477 of 1,510
distinct (word, lemma, pos) rows have a lemma that is not a simple extension
of the surface spelling** — `son`/`eran`/`avea`/`vuol`/`furon`/`convien`
restore to inflected forms (`sono`, `erano`, `aveva`, `vuole`, `furono`,
`conviene`) that the lemma (`essere`, `volere`, `convenire`, …) never
records, because the lemma is the infinitive and the restored form is not.
Old Layer 2 is therefore precedent for the split table but **not sufficient
data** for the normalization table — the target text has to be constructed,
not read off an existing column.

**A further 159 wordforms cross more than one POS** (`l'` → `lo`/`la`,
`fuor` → adverb `fuori` / verb, `qual` → four different POS across its
occurrences), and for these the restored spelling depends on which reading
applies — `l'` restores to `lo` or `la` only once gender is known.

### Why the pipeline is three steps, in this order

**Desk check, two lines (operator, 2026-09-09): the 159 cross-POS wordforms
are not an exception, they are the reason the pipeline has three steps in
this order.**

```
1. split          — L1 -> L2, closed-vocabulary, as designed above
2. POS             — per L2 entry, independent grammatical classification
3. normalize       — restore apocope/elision, keyed on (L2 text, POS from step 2)
```

*Inf* 1:1 `Nel mezzo del cammin di nostra vita`:

```
L1        0:Nel 1:mezzo 2:del 3:cammin 4:di 5:nostra 6:vita
1.split   (0,in)(0,il) (1,mezzo) (2,di)(2,il) (3,cammin) (4,di) (5,nostra) (6,vita)
2.POS     in=prep il=art mezzo=noun di=prep il=art cammin=noun di=prep nostra=adj vita=noun
3.normal. in→in il→il mezzo→mezzo di→di il→il cammin→cammino di→di nostra→nostra vita→vita
```

*Inf* 1:25 `così l'animo mio, ch'ancor fuggiva,` — no composite tokens, so
step 1 is the identity, but step 3 needs step 2's answer for `l'`:

```
L1        0:così 1:l' 2:animo 3:mio 4:, 5:ch' 6:ancor 7:fuggiva 8:,
2.POS     l'=article, gender/number undetermined until agreement with 2:animo
          (masc.sg) is resolved in the same pass
3.normal. l'→lo (only decidable once step 2 has fixed masc.sg); ch'→che;
          ancor→ancora; everything else passes through unchanged
```

**So the 159 wordforms are not a scoped exception: normalizing strictly
after POS, for every wordform, is simply step 3 following step 2 in a
three-step pipeline.** No `(wordform, pos)`-keyed carve-out is needed; the
ordering already gives every wordform its POS before normalization asks for
it. The other 1,527 wordforms just have a trivial step 2 → step 3 dependency
(the POS doesn't change the answer), not a different mechanism.

### Step 2 should be staged (operator, 2026-09-09)

Old Layer 2 asked for the whole row — POS, gender, number, person, tense,
mood — in a single judgment, and the participle finding above is what that
produces: deciding `verb`, `present participle`, `m.`, `sg.` together gives
the model enough surface area to substitute `adjective` for `verb`+participle
right at the one boundary where the two readings overlap. The fix is not
asking for less, it is asking **in stages** — a coarse category first, from a
closed set, then a further classification *within* that category (verb:
tense/mood/person/number; noun: gender/number; …), with the granularity of
the second stage decided separately, later. A coarse-only first pass is also
what would have kept the 39-value drift closed in the first place.

**The participle/adjective boundary needs pinning down explicitly, not just
staging.** Staging alone does not settle it: a participle stays `verb` at the
coarse stage only if the coarse-stage prompt or a one-shot example states the
rule, because "is this a verb or an adjective" is exactly the judgment the
model already answers both ways for the identical wordform (`smarrito` split
4/4). The design needs a stated convention — participles are `verb` at the
coarse stage regardless of predicative or attributive use, with the surface
reading recorded as a fine-grained tag under `verb`, never by relabeling the
coarse category — and a one-shot example enforcing it, not left implicit the
way old Layer 2 left it.

### The concrete task (operator, 2026-09-09)

Build the 442-wordform split table, the per-L2-entry POS classification, and
the ~1,686-wordform normalization table as **three separate passes in that
order**, with no view of old Layer 2, then **diff each against old Layer 2's
composite-POS/lemma field** as the precedent check — the same methodology
already standing in `PLAN.md` §2 and every `*/CORRECTIONS.md`: classify by
cause before touching anything, verify each row against an existing
precedent row. Three outcomes fall out, not two: the new table agrees (423
wordforms for the split table, expected); the new table disagrees and old
Layer 2 is the one that's wrong (`dal`'s `di+il` is the found candidate); or
the disagreement is genuine synchronic ambiguity the table must keep both
branches for (`nel`, and the 159 cross-POS wordforms, resolved by pipeline
order rather than a carve-out). Because normalization only ever consumes step
2's POS and never the other way around, a disagreement is never confounded
with a POS-tagging mistake.

### Execution mechanism

**Already exists (operator, 2026-09-09): `harness/`'s fixed-context step**
([`../harness/stages/09.md`](../harness/stages/09.md) §2). Each of the three
steps above, for each wordform, is one step `P -> O -> State Σ ()`: $P$ the
single instruction for that step ("split this token" / "classify this
entry's POS" / "restore this entry's spelling"), $O$ old Layer 2's row for it
(bootstrap precedent, premise 3) plus, for step 3, step 2's own output, $\Sigma$
the candidate entry, output the accepted text — and, per §9's design, **no
transcript carries between steps or between wordforms**, because each is
independent and a growing history buys nothing a stateless step doesn't
already have. Up to 3 × (442 + ~1,686) steps, each with a verdict (agrees /
precedent-is-wrong / genuine ambiguity) and no per-iteration context growth.

**One step, one job.** The three jobs are never compressed into one request —
against harness's own finding that batching is exactly where failures
concentrate (`harness/stages/09.md` §2, "Full rows, not a patch": 68% of the
paper it reviews attributes its failures to botched multi-key merges).

**Correction (operator, 2026-09-09): one *wordform* per request was wrong,
and is superseded by old Layer 2's own granularity — a chunk of lines,
`--chunk`, default 3.** This paragraph originally extended "no batching" from
the three jobs to the wordforms as well. That does not survive contact with a
request-rate limit: *Inf* 1:1-9 alone is 56 distinct wordforms against 3
chunks, and the corpus-wide table is 442. **The argument against batching does
not reach this case**, because a chunk is still *one job* asked over more
material — split these tokens — not split-plus-POS-plus-normalize merged into
one answer. The failure mode `stages/09.md` measures is a multi-key *merge*;
there is no merge here, only a list whose length the runtime knows in advance.

Two things follow, and both are improvements rather than costs:

- **The answer carries differences only** (operator, 2026-09-09, on seeing a
  real chunk answer: 27 rows to convey one fact). The request lists the
  chunk's L1 tokens; the answer names **only the tokens that split**, and a
  token with no row is recorded as a single word. *Inf* 7-9's real answer is
  one row, `del:di+il`. A key that names two places in the passage is refused
  and the model is told to prefix it with the preceding tokens
  (`trattar del:di+il`) — the target is the key's last word — which is also
  how a wordform genuinely splitting two ways in one passage gets said. **What
  this gives up, stated:** the one-row-per-token contract proved the model had
  produced a judgment for every token; an empty block is now
  indistinguishable from a model that did not look. `--check` against old
  Layer 2 is the after-the-fact detector, where a missed split shows as
  `differs`.
- **The alignment check is exact where it applies.** Each key is resolved
  against the tokens the request listed: it is exactly one token of this
  passage or the answer is refused. Old Layer 2
  needed `morph.align_chunk` for a different reason than a missing token
  layer: `tokenizer.tokenize()` predates both layers and
  `morph.validate_line` already checks rows against it. The reason is that
  `morph/morph.py`'s prompt shows only the raw lines and asks the model to
  *do the tokenizing too* ("emit exactly one row per word … separate words
  linked by an apostrophe into separate rows"), so its table has to be mapped
  back onto the lines afterwards — `morph.split_table` substring-matches the
  `Word` column with FIFO salvage at line boundaries, "tolerating LLM word
  transforms/hallucinations", and validation reports the damage after the
  fact. Listing the tokens in the request turns that tolerant post-hoc match
  into a gate the answer either passes or is refused by.
- **Repetition becomes a consistency check, and splits become per-occurrence.**
  A wordform occurring in two chunks is asked twice, and **both readings are
  kept**: `gen2/l2.py` records a split at `(line, l1_index)`, not against a
  wordform-keyed table, so `nel` = `in+il` at 1:1 and `ne+lo` at 3:2 can both
  be true. A later occurrence answered differently from the first is recorded
  as a **conflict** on that chunk and then applied as answered — the model had
  that passage in front of it. This is exactly the handful of flagged
  exceptions this file already predicts (old Layer 2's own `dimmi` noise is
  the same shape), and the per-wordform granularity could not perform the
  check at all. The wordform-keyed table this file describes is then what a
  corpus-wide run *derives* from these occurrences, with the disagreements
  visible instead of averaged away.

**A chunk that never passes the gate degrades to line by line**, which is
`morph.py`'s own fallback ("chunk failed, retrying line by line"), so one bad
group costs its own lines and not the run.

**The split step's output is keyed by the word, not by `l1_index`.** (This
survives the granularity correction above unchanged — a chunk's answer is a
list of `word:split` rows, still never an index.)
Writing the answer as `1:in`, `1:il` — echoing the numeric index back for
each half of the split — puts load on the model the task doesn't need:
getting the split right and copying a number correctly are two different
failure modes bundled into one answer, and only the first is what step 1 is
actually asking. The step should instead ask for `nel:in+il` — the surface
word as the key, its split as the value — with `l1_index` attached by code
afterward from the wordform's own position, the same way alignment already
anchors Layer 3 spans to tokens without asking the model to state indices.
**The ambiguity retry this paragraph originally specified is gone with the
granularity change**: it existed because a wordform asked in isolation
sometimes cannot be decided (the `nel` two-way case). A chunk carries its
lines, so the model has the context that question needed and answers the
reading this passage takes; a disagreement across chunks surfaces as a
recorded conflict instead. This is an implementation detail of step 1
specifically — it does not change
the split table's scope or the three-step ordering.

### Cost, stated once (`REDESIGN.md` §5)

```
composite-POS tokens          2,681
terminals after splitting     5,374   (+2,693)
corpus                      101,601 → 104,294   (+2.65%)
```

Almost all are two-way splits; three-way ones are `verb+pronoun+pronoun` (6)
and `preposition+article+noun` (4). The largest classes:

```
preposition+article 1,984   verb+pronoun 488   pronoun+pronoun 61
pronoun+preposition 58      adverb+pronoun 42  preposition+noun 12
```

**What the current merge costs, measured.** Of the 1,984 `preposition+article`
tokens, Layer 4 can only give the token one `deprel`, which goes to the
preposition half; the article half gets no edge. The noun it determines
therefore has **no determiner child in 1,666 cases**. The 318 exceptions
carry a separate `det:poss` (294) or an actual second determiner (24 — these
want checking). So: the relation `la → via` is an edge at *Inf* 1:3 and is
absent at *Inf* 1:1, and the only difference is that a contraction happened.
This holds under enumeration too: without the split, `il` cannot be a member
of the phrase it determines. The terminal decomposition is motivated
independently of what is built above it.

The tail of the composite-POS inventory also contains spacing variants
(`verb + pronoun` 2, `preposition + article` 1) — Layer-2 hygiene rather than
a design matter, but it belongs on the list.

### What L2 does and does not renumber

Old Layers 1–5 keep the addressing they already have; nothing in the design
edits `dep/`, `np/`, `skel/`, or `case/` in place. L2's split is not a second
blind renumbering on top of L1: every L2 entry carries the `l1_index` it came
from, so the old-to-new correspondence is data, not something a consumer has
to reconstruct.

### Bootstrap status (premise 3)

Old Layer 2's composite-POS and lemma columns are used once, as bootstrap
precedent for building and checking the split/POS/normalization tables
(premise 3) — never as an input the running L2 pipeline reads. The three
passes read L1 and, per step, each other's own prior-step output; no
generation-2 definition names an old-generation file.

## Rollout plan (operator, 2026-09-09)

**Canto 1 first, starting at *Inf* 1:1-9 and widening gradually, before any
pass runs corpus-wide.** Every measurement above was corpus-wide from the
start, but running the three-step pipeline itself corpus-wide first would
repeat the mistake premise-checking exists to avoid: 442 + ~1,686 wordforms
is enough surface area that a systematic prompt or pipeline-ordering error
could pass a spot check and still be wrong at scale. `reads/inf-1-1-9.md`
already established the same discipline for reading — nine lines, findings
measured corpus-wide only *after* being seen concretely — and the
split/POS/normalize build should follow it rather than start from the
opposite end. Concretely: run all three passes over *Inf* 1:1-9 only,
hand-inspect every wordform's split, POS, and normalization against the
source (the *Inf* 1:1 and 1:25 worked examples above are the first two data
points), widen to the rest of *Inf* 1 (136 lines), only then the full
corpus.

## Implementation: step 1 only (`gen2/l2.py`, 2026-09-09)

**Scope: the split. Steps 2 and 3 are not implemented** (operator: 「まず単語の
分解だけ実装してください」). `gen2/l2.py` assigns no POS and restores no
spelling — `ch'` stays `ch'`, `i'` stays `i'`, `cammin` stays `cammin`.

**One decision this file had to settle first.** *Execution mechanism* above
puts old Layer 2's row in $O$ as bootstrap precedent; *The concrete task*
says build "with no view of old Layer 2", then diff. **The second is
adopted** (operator, 2026-09-09): agreement with `morph/` has to be evidence,
not an echo of having been shown the answer. The model sees the passage and
its tokens and nothing else; old Layer 2 enters once, afterwards and offline,
through `--check`.

**Granularity is old Layer 2's** — `--chunk`, default 3 lines per request,
matching `morph/morph.py --chunk 3` — per the correction recorded under
*Execution mechanism* above. Over *Inf* 1:1-9 that is **3 requests, not 56**.

The pieces:

- **`L2Entry(l1_index, text)`**, **`L2Line(no, entries)`** — frozen
  dataclasses with `to_dict()`, mirroring L1's shape. The L2 token number is
  the position in `entries`; only `l1_index` is data, as designed.
- **`is_splittable(token)`** — a token with no letter never splits, so
  punctuation costs no model call. This is a deterministic reading of L1's
  own output, not a fact borrowed from old Layer 2.
- **`chunks(lines, size)` / `asked_tokens(chunk)`** — the unit of work, and
  the chunk's splittable tokens in L1 order. `chunks` is `morph.py::_chunks`.
- **`apply_splits(line, splits) -> L2Line`** — the pure half. `splits` is
  keyed by position, `(line number, l1_index)`. A token with no split passes
  through verbatim, casing and apostrophe kept, which is also what an
  *unanswered* token gets: a failed step degrades to the identity, never to a
  hole in the line.
- **`ask_message(chunk, refusal="")`** — $O$: `<lines>` for context,
  `<tokens>` to fix the boundaries, `<verdict>` saying which of the two
  situations this is.
- **`locate_key(key, tokens)`** — which token a row's key names. One token, or
  a run of consecutive tokens **ending with** the one being split. A key
  matching two places is refused with both lines named, rather than applied to
  both — those two places are exactly where a wordform can split two ways.
- **`parse_split_answer(text, tokens) -> (splits, error)`** — the runtime
  gate: exactly one `<split>` block, **only rows for tokens that split**, each
  key resolving to exactly one token, each value 2-3 non-empty whitespace-free
  parts. A row restating a token unchanged, a token named twice, or a key that
  is not a run of this passage's tokens refuses the whole answer. An empty
  block is a valid answer meaning "nothing here splits".
- **`split_chunk(...) -> ChunkResult`** — the bounded step. Every attempt
  calls `generate.reset()` and sends exactly `[system, user]`, so no
  transcript crosses a chunk *or a retry*; a refused attempt records nothing
  and re-asks with the reason (`harness/stages/09.md` §2.1's "refusal is the
  identity morphism"). Budget 3, a cost cap. Acceptance is `accepted`, a fact
  about the gate — never `bool(answers)`, since "nothing splits here" is a
  settled answer.
- **`build_splits(...) -> dict[(line, l1_index), parts]`** — one step per
  chunk; a group that never passes is **retried line by line**; each
  occurrence keeps its own reading, and a wordform answered differently from
  its first reading is recorded as a conflict. `on_settled` streams each
  chunk's record to the log sink as it settles.
- **`render_artifact` / `parse_artifact` / `artifact_path`** — the TSV, `line
  l1_index l2_index text`, written to `layers/l2/<canticle>/NN.tsv`, the
  shape every other layer in this repository already uses. **`gen2/` is a
  code directory: no artifact and no run log is written into it** (operator,
  2026-09-09). `l2_index` is written down because a flat file has no order to
  lean on; it is derived from the entry's position, not decided.
- **`check_against_precedent(l1_lines, l2_lines, morph_rows)`** — the offline
  diff. Old Layer 2's split is read off the `lemma` column (`+` means
  composite; a non-composite row's lemma is a lemma, not a split, so the
  wordform stands for itself), and **every distinct reading is kept, never
  collapsed to a majority** — that is what makes the genuine-ambiguity
  outcome visible at all — and `our_splits` does the same for this artifact,
  since its splits are per occurrence. Verdicts: `agrees`, `differs`,
  `ours-ambiguous`, `precedent-ambiguous`, `absent`. Which of L2.md's two
  non-agreement outcomes a `differs` row is remains a judgment recorded here,
  not something the checker decides.

**Standing patterns.** The CLI holds [`../ARCHITECTURE.md`](../ARCHITECTURE.md)'s
§0 checklist, which is binding on new entry points:

- **§2 model access** — `dante_corpus.harness.llm.llm7shi_generate`, imported
  lazily inside `_main`; the loop itself takes `generate` as an injected
  callable and never imports llm7shi, so importing `l2.py` touches no network.
  `reset()` at every step boundary.
- **§4 observability** — a `HarnessStatusLine` bar labelled `{canticle}
  {canto}` **whose numerator walks that canto's Dante lines** as each chunk
  settles, exactly the `skel/`-driver pattern §4 names; its **stream shared
  with llm7shi** (`file=ui_stream`) so streamed model output coexists with the
  bar; a `progress_separator` major `[1/1]` line naming the corpus position;
  one progress line per chunk with its compact result and elapsed seconds; 429
  backoffs counted through the stream's `wait_retry` hook
  (`retry_snapshot`/`retry_delta` → `api_retries` / `api_retry_seconds`).
- **§5 streaming JSONL** — one `chunk` record per settled chunk, written and
  flushed by the `on_settled` callback as it settles (never accumulated to a
  phase boundary), the adapter's `llm_request`/`llm_response` pair on the
  same sink, and `report.metrics()` as the final `summary` record — the
  completion marker. Timings are **summed per-step seconds, never a
  start-to-end wall span**, and there is no `started_at` field. Resume-or-
  truncate is chosen explicitly: this pass **truncates** (`"w"`, one file per
  attempt), because a split table over a closed vocabulary is not
  incrementally repairable the way a canto's rows are and a half-built table
  must never pass for a finished one. **The log follows the artifact, one per
  canto**: `--log` takes no filename, it writes `NN.tsv`'s records to `NN.log`
  beside it. A named file stopped making sense once `-c` could select several
  cantos — every canto's records would pour into whichever single file the
  command line happened to name. The adapter's own `request_log` is bound once,
  at construction, so a small relay object forwards it to whichever canto's log
  is open and the run keeps one `generate`.
- **§6 reporting** — `SplitReport` ships both faces, fed from exactly the
  records the log carries, so the summary record and the printed text cannot
  drift. The gate appears with its threshold (`gate == 0 lines: PASS/FAIL` —
  a line no attempt ever answered, the group-failed-then-recovered case
  excluded); `slow_steps` counts steps at or past the 300 s benchmark
  standard; `conflicts` carries every wordform answered two ways.
- **§7 errors** — a gate refusal becomes text in the next request, never an
  exception into the generation loop.
- **§8 tests** — no model, no network; scripted stub through the real parser.
- **§9 CLI skeleton** — `-m/--model` / `--chunk` / `--max-iterations` /
  `--log` / `--verbose` / `--temperature` / `--started-at`, over the corpus's
  own driver shape (canticles positional, `-c` a canto spec): a run header per
  canto, `try/finally` sink close, a final `records written to ...` line then
  `report.summary()`.
- **§3 wire protocol is the one override**, and the plan says so: there is no
  `<tool_call>` XML because there are no tools. This is the fixed-context mode
  (`harness/stages/09.md` §2) — the runtime holds the gate and the model's
  whole output is one `<split>` block, exactly as Layer 5's is one `<rows>`
  block.

The prompt is a file, not a string constant:
[`gen2/skills/l2-split/`](gen2/skills/l2-split/) (`SKILL.md` + `answer.md`),
loaded through `dante_corpus.harness.skills.Skill`, its `digest()` in the run
log's summary.

```
uv run python -m layers.gen2.l2 inferno -c 1 --lines 1-9 \
    -m google:gemma-4-31b-it --log
uv run python -m layers.gen2.l2 inferno -c 1 --lines 1-9 --check
```

The command line is the corpus's own driver shape (`skel/skel.py`, `dep/dep.py`):
**canticles positional, `-c` a canto spec** — `1`, `12-`, `-20`, `1,3-5,11-` —
resolved by `api.select_cantos` against the cantos the canticle actually has, and
`api.check_canto_spec` failing a typo at the command line rather than part-way
through. Omitted, it means every canto, one artifact each, over one model
connection and one log.

`--lines` narrows further, within **one** canto, and defaults to the whole of it;
asking for two cantos and a line range is refused rather than guessed at. A
canto's length is its own — 136 lines here, something else next door — so a range
that had to be named would have to be looked up per canto, and naming one is the
exception (the nine-line pilot above), not the rule.

## The live pass over *Inf* 1:1-9 (`google:gemma-4-31b-it`, 2026-09-09)

**The rollout plan's first rung, run.** *Inf* 1:1-9 is **74 L1 tokens**
(punctuation included) over **56 distinct wordforms**, asked as **3 chunks of
3 lines = 3 requests**, 68 tokens answered. Numbers, per `ARCHITECTURE.md` §5:

```
chunks        3 settled, 0 refused, 0 line-by-line fallback
requests      3 attempts, 0 refused, 0 api retries
seconds       47.3 total (14.4 / 13.6 / 19.4)
tokens        68 answered — 4 split, 64 left whole
terminals     74 L1 tokens -> 78 L2 entries (+4)
conflicts     0        unresolved lines  0
--check       56 agrees, 0 differs, 0 ours-ambiguous, 0 precedent-ambiguous
```

The model listed **exactly four rows across the three answers** and nothing
else: `Nel:in+il` and `del:di+il` (1:1), `nel:in+il` (6:2), `del:di+il` (8:4).
No key needed a disambiguating prefix. Hand-inspected against the source, the
silences are as right as the rows:

- **Elision left alone** — `ch'` (8:5, 9:5), `i'` (8:6, 9:6), `v'` (9:7),
  `Tant'` (7:0), `l'` (9:2) all pass through verbatim. These are step 3's, and
  the prompt's most-likely-to-be-wrong list named them.
- **Apocope left alone** — `cammin` (1:3), `ben` (8:4), `trattar` (8:2),
  `pensier` (6:2), `dir` (4:3), `qual` (4:4).
- **`de` (9:1) not split**, correctly: it is a plain preposition here, not a
  contraction, and it is the nearest thing in the passage to a trap.

So the model's answers are verified for this passage, alongside the plumbing,
the observability, the artifact and the checker. **What this passage cannot
show** is the differences-only contract's own failure mode at scale: it holds
only four splits, and a silent overlook would have surfaced here as a `differs`
in `--check`. Wider ranges are where that gets tested.

**Tests.** [`tests/test_gen2_l2.py`](tests/test_gen2_l2.py), 66 tests
(`uv run pytest layers/tests`, 79 with L1's) — no model, no network: a
scripted stub routed through the real parser.

## What is still open

- **Widening.** The rollout plan's next rungs: the rest of *Inf* 1 (136 lines,
  ~46 chunks), then the corpus. Nine lines held four splits and no hard case;
  the rest of the canto is where the contract meets clitic compounds
  (`verb+pronoun`) and a key that actually needs a disambiguating prefix.
- **The differences-only contract's blind spot, unmeasured.** An overlooked
  token and a token judged whole look the same in the answer. `--check` caught
  nothing at 1:1-9 because there was nothing to catch. A wider run is what
  turns that from an argument into a number.
- **Steps 2 and 3.** No POS pass, no normalization pass. The three-step
  ordering is designed above and nothing in `gen2/l2.py` prejudges it.
- **Build order.** L4 (dependency) precedes L3 (phrases) in the rebuilt
  stack despite the numbering — L3 must project from generation 2's own L4,
  never from old Layer 4 (`REDESIGN.md` §5). This does not block L2, which
  only depends on L1.
- **The bootstrap safe/contaminated split** for everything past L1 — which
  frozen layers are a safe one-time warm start and which are contaminated
  positions the model must not anchor to — is discussed but not settled
  (`PLAN.md`'s *Still deferred* note). Load-bearing for L2's POS-classification
  step specifically (old Layer 2's `pos` vocabulary is one of the named
  contaminated candidates), irrelevant to the split table itself (closed
  vocabulary, no model call needed there beyond flagged exceptions).
