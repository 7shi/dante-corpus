# L1: terminals, punctuation included

Everything `PLAN.md` and `REDESIGN.md` say about generation 2's Layer 1,
gathered in one place. L1 is the only layer of the rebuilt stack that is both
**designed** and **implemented** — see *Implementation* below.

## What old Layer 1 gets wrong

`PLAN.md`'s handoff (Layer 1 review): nothing is discarded at the text level —
`Line.text` (`dante_corpus/api.py:249`) keeps punctuation verbatim. Only
`Line.tokens` (`api.py:52`) filters it, via `has_alpha`, **before** assigning
any index. So the defect is not that punctuation is lost; it is that it never
receives an address. No layer built on top of `Line.tokens` can cite a comma,
a colon, or a quotation mark, because none of them has a token position to
cite.

`REDESIGN.md` §1 restates the same fact at the level of the whole stack: the
stack is not missing a tree — Layer 4 already is one — it is missing
**constituent nodes**. Two of the corpus's own devices compensate for
Layer 1's token shape in opposite directions: Layer 2's composite POS
(`preposition+article`, `verb+pronoun`, …, 2,681 tokens) folds several
grammatical words **into** one token; Layer 4's `expl` (1,466 occurrences)
discards a token that is **smaller** than a grammatical word. Locating both
compensations at Layer 1 is what motivates rebuilding it before anything
above it.

## The design (`REDESIGN.md` §2.1)

**L1 is `tokenize()`'s full output, indexed** — alpha tokens and punctuation
tokens alike, each with its own `(line, token)` address. This is not the same
sequence as old Layer 1's `Line.tokens`, which applies `has_alpha` before
indexing and so never assigns punctuation a position at all. L1's numbering
therefore does not line up with old Layer 1's — a line with punctuation has
more L1 tokens than old-Layer-1 tokens, and every alpha token's index shifts
accordingly past the first punctuation mark in the line.

`tokenize()` (`dante_corpus/tokenizer.py`) already splits punctuation into its
own token strings; the only filter old Layer 1 applies is `has_alpha`, which
drops them *before* indexing. So `PLAN.md`'s original finding — "punctuation
has no token index, so no layer can cite it" — is not a tokenization gap, it
is an indexing one, and L1 (not L2) is what fixes it: L1 is `tokenize()`'s
output taken whole, minus only the pure-whitespace tokens `tokenize()` also
produces (a space is not a terminal).

Since the design stops at phrases rather than building a full sentence tree
(`REDESIGN.md` premise 2), punctuation belongs **beside** phrase-structure
objects, not beneath them: a comma separates coordinated phrases, a colon
introduces one, quotation marks bound a span of direct discourse — none of
that is a property of any single token, so it needs to sit at the terminal
level rather than be swallowed by it.

### Punctuation measurement

Corpus-wide, from the frozen source text (`src/*/*.txt`), gold not consulted:

```
alpha tokens (current Line.tokens)                       101,601
punctuation tokens (tokenize(), non-alpha, non-space)      17,434
  ,  8,513   .  3,275   ;  1,628   «/» 1,062/1,062   :    988
  ?    278   !    232   ‘/’  109/109   “/”   51/51   '     51
  —     18   (/)     3/3    -      1
```

**Every quotation-mark pair is exactly balanced** — `«`/`»` 1,062/1,062,
`‘`/`’` 109/109, `“`/`”` 51/51. The closing partner a punctuation-aware layer
would need to bound a quoted span as a terminal-delimited constituent already
exists one-to-one — this is the address `PLAN.md`'s open survey item "the
quotes hierarchy" has been missing.

### What L1 does and does not renumber

Old Layers 1–5 keep the addressing they already have; nothing in the design
edits `dep/`, `np/`, `skel/`, or `case/` in place — the rebuilt stack is a
parallel generation, not an in-place edit (premise 1). What *does* shift is
L1 itself against old Layer 1: L1 has its own numbering, not a superset or
subset of `Line.tokens`'s, because punctuation occupies positions old Layer 1
never assigned.

L2 (grammatical words, splitting composite L1 tokens — `REDESIGN.md` §2.1,
not yet implemented) is not a second blind renumbering on top of L1: every L2
entry carries the `l1_index` it came from, so the old-generation
correspondence and the L1-to-L2 correspondence are both data, never something
a consumer has to reconstruct.

### Bootstrap status (premise 3)

Generation 2 must not depend on generation 1 at rebuild time
(`REDESIGN.md` premise 3): old Layers 1–5 may be used once, as bootstrap
material, but no generation-2 layer's *definition* may name an old-generation
file as an input. L1 satisfies this trivially — it reads only the frozen
source text (`src/*.txt`, layer-0, not old Layer 1) through
`dante_corpus.tokenizer.tokenize()`, the same deterministic function old
Layer 1 itself calls before applying `has_alpha`. There is no model call
anywhere in L1's construction, so the bootstrap question that matters for L2
onward (which frozen layers are a safe one-time warm start vs. a contaminated
anchor, `PLAN.md`'s *Still deferred* note) does not arise for L1 at all.

## Implementation (`gen2/l1.py`, this session, 2026-09-09)

`gen2/l1.py` implements the design above exactly:

- **`tokenize_l1(text) -> tuple[str, ...]`** — `tokenize()`'s full output with
  only pure-whitespace tokens (`str.isspace()`) dropped; alpha and
  punctuation tokens both survive.
- **`L1Token(index, text)`**, **`L1Line(no, text, tokens)`** — frozen
  dataclasses, each with `to_dict()`.
- **`l1_line(no, text) -> L1Line`** — indexes one line.
- **`l1_canto(canticle, number) -> tuple[L1Line, ...]`** — indexes a whole
  canto by reading raw source text through `dante_corpus.api.canto()`, the
  only thing it touches in `dante_corpus` (layer-0 text access, not old
  Layer 1 — premise 3 holds).

No model call, nothing persisted: L1 is a pure function of the source text,
computed on demand the same way old Layer 1's `Line.tokens` already is —
there is no artifact to build or fix.

**Verification.** The *Inf* 1:1 and 1:25 worked examples from `REDESIGN.md`
§2.1 reproduce exactly (`Nel`→index 0, `del`→index 2, each followed by the
next alpha token unshifted; `l'`→index 1, the first comma→index 4, `ch'`→
index 5). A `--stats` corpus-wide census matches §2.1's own numbers bit for
bit: 101,601 alpha terminals, 17,434 punctuation terminals with the same
per-mark breakdown, every quotation-mark pair exactly balanced.

**Tests.** [`tests/test_gen2_l1.py`](tests/test_gen2_l1.py), 13 tests
(`uv run pytest layers/tests`) — parallel to `harness/tests`, not part of
the root suite (`pyproject.toml` `testpaths = ["tests"]`) until `gen2/`
replaces the old stack, at which point the tests move into root `tests/`
alongside it.

## What is still open

- **L2** (grammatical words, `(l1_index, text)` pairs, splits only, three-step
  split → POS → normalize pipeline) — designed in full (`REDESIGN.md`
  §2.1, `PLAN.md`'s handoff) but not implemented. Its rollout plan (Canto 1,
  *Inf* 1:1-9 first) is the next concrete step once started.
- **The bootstrap safe/contaminated split** for everything past L1 — which
  frozen layers are a safe one-time warm start and which are contaminated
  positions the model must not anchor to — is discussed but not settled
  (`PLAN.md`'s *Still deferred* note, `REDESIGN.md`'s *Still unwritten* note).
  Irrelevant to L1 itself (no model call), load-bearing from L2 on.
